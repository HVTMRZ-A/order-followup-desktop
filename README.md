# 订单跟进工作台

面向 Windows 的本地订单跟进桌面应用。当前版本为 **v0.4.9**；下载与更新内容见[发布说明](https://github.com/HVTMRZ-A/order-followup-desktop/releases/tag/v0.4.9)。

订单管理作为主数据，关联计划行、包材和每日异常。新版本完整展示物料编码与原单明细、留存原文件；支持拖拽自动分流、待办勾选确认、分析后的分仓检查提醒及关联计划行经确认更新。计划总表位于每日跟进下面。

订单导入 / 保存后预览确认加入计划总表；逐行展示目标表和数据，确认后追加或补空白，冲突不覆盖，不能加入和未确认事项保留为订单关联待办。支持补充资料后重新处理与去重。

导航依次为今日待办、订单管理、包材跟进、每日跟进、计划总表、设置与更新。

新增“计划总表”入口：完整导入、查看、编辑和另存原总表的 7 张可见工作表（含包材交期、采购回复与出货计划），隐藏表排除。数据含历史记录和原表全部有效列，保存在本机；原公式、图片和图表在另存时保留。公式由 Excel 重算。

下载：[最新 Windows 版本](https://github.com/HVTMRZ-A/order-followup-desktop/releases/latest)

## 已实现

- **日常操作优化**：格式设置默认收起并记忆展开状态；选中格有深蓝边框，计划长内容可在完整内容栏查看复制。待办支持搜索、高优先级筛选及明确处理按钮；包材支持搜索、逾期筛选及选中信息；每日跟进可搜索勾选关联订单。导入后定位新订单，导出统一使用计划总表入口。

- 新订单手动登记与 Excel `.xlsx` / CSV 导入，模板导出、预览、重复订单拦截、整批事务保存。
- **拖拽导入**：把生产单 / 模板直接拖进窗口，遮罩提示后松手，解析完先给确认预览再入库；多文件合并预览。
- **生产作业计划单直接导入**：按表头文字自动识别合同编号、客订编号、交期、经办人与产品明细行，不要求固定单元格位置；识别不到的字段留空并提示，不猜值。
- **订单管理**：物料编码、数量、原单要求及自定义列留存，原文件可原样导出；旧记录可经确认补充空白资料。
- **编辑与删除**：直接编辑整单或所选型号；删除型号同时移除其包材和待办，支持整单删除。确认时可选择保留或清空关联计划行输入值；自动备份并保留回收站，可恢复订单、型号及包材，不覆盖后续修改。
- **完整计划总表**：7 张可见表统一导入、查看、编辑和另存，历史值、原公式、图片和图表保留，隐藏表排除。确认加入的计划行绑定订单和型号。
- **计划表保存、删除与导出**：自动保存并显示最近保存时间，显式“保存到本机”及 Ctrl+S 可提交当前输入；保留唯一“导出”入口，范围可选全部、当前或勾选多个 sheet。支持批量清空输入值和移除计划记录，原订单、空行、公式及格式保留，操作可撤销；移除前自动备份。部分导出去掉未选工作表及其独有附件，并整理共享字符串。
- **表格层级与格式**：显示原表合并标题、纵向合并、列宽、行高和对齐；订单与子项用分组线和分支线区分，搜索保留整组明细，旧总表无需重新导入。
- **表格编辑**：计划表、订单管理及包材明细统一为单击选择、直接键入替换，双击 / F2 编辑原内容；Enter 向下、Tab 向右并保存，Shift 反向，Esc 取消。关联计划字段写回订单，其他关联行留待确认更新；公式和自动计算结果只读。
- **原表颜色**：计划总表保留单元格的固定底色、字体色、主题色和索引色，包括有效范围内有颜色的空格；可关闭“显示原表颜色”切回白底，交替行底色保持关闭。旧总表自动补齐颜色，保留后续修改。条件格式规则暂不计算显示。
- **文字与单元格调整**：计划总表、订单管理及包材明细支持选区批量改字体、字号、加粗、倾斜、下划线、文字和填充颜色、水平及垂直对齐、自动换行；Ctrl+B/I/U 切换字形。拖动行列边界、双击自动适应、数值设置及表头右键菜单可调整尺寸。修改保存在本机并支持撤销、重做；计划表另存 Excel 时保留这些格式和尺寸，公式及其它源格式不变。
- **撤销 / 重做**：顶部按钮及 Ctrl+Z / Ctrl+Y（或 Ctrl+Shift+Z），支持本次打开期间最近 100 次计划表、订单和包材格内修改、包材详情、计划新增行和每日记录修改；一次计划修改涉及的订单与分析后跟进记录一起回退。输入框内先撤回未提交文字；重新导表、恢复备份或冲突时保护后续数据。
- **确认更新**：新增、补空白、更新关联行分别预览；关联行变化需勾选确认，未知冲突保留待办。分析完成会生成关联订单的分仓检查提醒。
- **待办清单按订单折叠**：同单多条待办合并成组，单击 `＋/－` 展开收起，只一条时平铺。
- 订单、合同号、销售订单号及各自经办人关联。
- 整单或按型号确认工程 BOM、分析、包材信息及跟进完成。
- 合同接单满 24 小时未确认提高优先级；分析满 10 个自然日未确认包材信息提高优先级。
- 包材请购数量 = 对应型号产品数量 × 该包材单件用量（十进制定点计算）。
- 按填写的提醒日期在本机时间 09:00 提醒；未填写提醒日则采用预计到料日期；分批到料可累计登记。
- 分仓、成品入库、销售出库每日跟进记录；历史未解决事项持续显示。
- 系统托盘、可选开机启动、本地数据备份与恢复。
- 从公开 GitHub Release 检查更新、下载 SHA-256 校验、数据库自动备份、原子替换程序并重启。
- 下载连接重置或超时会重试（最多 4 次），切换 GitHub 官方 API 入口并续传；失败保留进度，重新点击检查可继续。设置中可打开更新日志和手动下载页。

## 使用

下载 ZIP 后解压到可写目录，运行 `OrderFollowup.exe`，无需安装 Python。
真实业务数据仅保存于 `%LOCALAPPDATA%\OrderFollowupDesktop`，不会上传至仓库或 GitHub。

工作台不操作云星空，不自动刷新外部系统；BOM、分析均为用户确认项。
09:00 准点提醒要求电脑开机且程序运行；未运行时打开程序补查。详见 [使用说明](docs/使用说明.md)。

## 开发与构建

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe scripts/build.py
```

开发测试可设置 `ORDER_WORKBENCH_DATA` 指向独立测试目录。
发布时更新 `workbench/__init__.py` 的 `VERSION`，构建并在同名 GitHub Release 附上 `OrderFollowup.exe`、ZIP 和 `SHA256SUMS.txt`；正式 Release 的 EXE 资产须提供 GitHub SHA-256 digest。程序只接受固定仓库的正式三段式版本。

## 数据与设计

SQLite 存储结构版本为 1；订单包含型号与包材明细。配置、每日记录与保存历史独立保存。
整单确认是对当前全部型号的批量操作，新增型号不继承先前确认。整单完成由全部型号“跟进完成”汇总，撤销任一型号完成后恢复其提醒。
导入仅新增订单，已有订单不自动覆盖。接单日期仅填写日期时按当天 00:00 计算。
